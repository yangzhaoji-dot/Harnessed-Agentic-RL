## 1. Harness-Zero: Harness Distillation via Agent-as-Harness
- arXiv: [2609.24974](https://arxiv.org/abs/2609.24974) — submitted 2026-09-21
- **Priority:** Critical / direct internalization collision
- **Key idea:** evolve or otherwise obtain a specialized harness, adapt its guidance into a private reference harness for a separate "harnessing agent", let that agent review/correct the student's proposed responses *before execution* in the student's target action space, then SFT the accepted trajectories. The specialized harness and reviewer are removed at deployment.
- **Reported result:** on SpreadsheetBench Verified, AppWorld, and USPTO retrosynthesis, Qwen3.5-9B improves from a 23.3% macro average under the minimal target harness to 44.3% after distillation, exceeding the 41.7% achieved by attaching the evolved harness itself. The paper reports 82.3% average recovery of 28 harness-induced behavior patterns.
- **Why it matters:** this is substantially stronger evidence for **external Harness -> policy internalization** than simple assisted-vs-unassisted training. It also shows that direct imitation of trajectories collected under the strong harness can fail; translating privileged harness guidance into the *student's native action space at the response boundary* is the important step.
- **Relation to our direction:** a generic "learn with Harness, remove Harness later" contribution is now unsafe. The remaining sharper question is **which component should remain external, which is actually internalizable, at which state/training stage, and how to measure component-level marginal value before handoff**. Their own result that procedural behavior internalizes more easily than deep domain knowledge supports an explicit internalization/externalization boundary rather than uniform retirement.

## 2. Uni-Agent v0.1.0: Train Long-Horizon Agents at Scale
- Release/blog: [verl project, 2026-09-24](https://verl-project.github.io/posts/2026-09-23-uni-agent-v0-1-0/)
- Repo: [verl-project/uni-agent](https://github.com/verl-project/uni-agent)
- **Priority:** High / practical infrastructure baseline
- **Key development:** an open long-horizon agent-RL framework that can plug existing harnesses (including Claude Code-style harnesses) into RL while preserving exact rollout tokens. It explicitly handles context trimming/branching with trajectory splitting and handles discarded/retried actions with trajectory rollback so abandoned tokens do not enter the training signal.
- **Why it matters:** this is unusually relevant to any Adaptive Harness implementation because adaptive harnesses naturally rewrite context, branch histories, retry actions, and discard suffixes. Those operations are not neutral bookkeeping: if the trainer re-tokenizes or trains on abandoned actions, the resulting policy gradient no longer corresponds to the actual executed harness trajectory.
- **Relation to our direction:** our method should treat **Harness state transitions and trainable-token bookkeeping as first-class objects**. In particular, branch/rollback experiments need a precise rule for which suffix tokens remain in the policy loss. Uni-Agent is therefore a strong implementation substrate/baseline even though it does not itself learn a state-conditioned Harness policy.

## 3. Reinforcing Agents with Collective Skills (Skill2Env)
- alphaXiv/paper page: [Reinforcing Agents with Collective Skills](https://www.alphaxiv.org/abs/2609.reinforcing-agents-collective-skills) — submitted 2026-09-21
- Repo: [NVlabs/Skill2Env](https://github.com/NVlabs/Skill2Env)
- **Priority:** High adjacent / skill-to-RL-data internalization
- **Key idea:** compile ~3.4k public Agent Skills into 7,971 executable terminal RL environments with programmatic tests plus Skill-derived behavioral rubrics. A DPPO-style run on Qwen3.8-27B improves Terminal-Bench 2.1 by +4.7 pp and S2EBench pass rate by +4.3 pp.
- **Process-reward finding:** adding Skill-derived rubric reward makes trajectories follow the documented procedures more closely, but lowers benchmark task completion relative to outcome-only RL. The behavioral target and the task-success target are therefore measurably misaligned.
- **Why it matters:** external procedural knowledge does not need to remain a runtime Skill; it can be transformed into **environment structure + verifier/rubric**, then absorbed by policy training. But the rubric result is a warning against collapsing "follow the desired process" and "solve the task" into one scalar objective.
- **Relation to our direction:** for Harnessed Agentic RL, this suggests separating **Harness/process credit** from **task utility**, and measuring whether a component teaches transferable behavior or merely imposes a preferred workflow. For Creative/Research Agents, Skill-derived research workflows could become scalable process supervision, but diversity/novelty should remain a separate objective from procedural compliance.

## Method implication to retain

Two boundaries are now sharper:

[
	ext{Harness usefulness} 
eq 	ext{Harness internalizability}.
]

A component can improve the rollout yet still be poorly transferable into model weights (e.g. external tools/domain knowledge), while procedural control can often be distilled. A stronger Adaptive Harness formulation is therefore:

[
U_i(s_t,pi_k,B)
quad	ext{and separately}quad
I_i(s_t,pi_k),
]

where (U_i) is the current marginal utility/cost of external component (i), and (I_i) is evidence that its behavior can be reproduced without that component.

For branch/rollback training, exact trajectory semantics also matter:

[
	ext{executed suffix} ightarrow 	ext{trainable tokens},qquad
	ext{discarded/rolled-back suffix} ightarrow 	ext{no policy loss}.
]
